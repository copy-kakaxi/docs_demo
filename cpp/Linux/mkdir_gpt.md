# `mkdir`：创建目录

> **核心作用**：创建一个或多个目录。最重要的选项是 `-p`（自动创建缺失的父目录）、`-m`（指定新目录权限）、`-v`（显示创建过程）。

## 1. 基本语法与行为

```text
mkdir [选项]... 目录名...
```

- 可以一次传入**多个目录名**。
- 默认只能在父目录已存在时创建最后一级目录；否则报错。
- 默认情况下，**目标目录已存在**也会报错；加 `-p` 后，目标已是目录时不因“已存在”报错。
- 新建目录的默认权限通常由初始权限 `0777` 与当前 `umask` 共同决定。

::: tip 理解 `mkdir` 的核心
`mkdir` 创建的是**目录对象**，不是普通文件。它不会自动往目录里写任何文件；创建成功后目录通常为空（除了文件系统意义上的 `.`、`..`）。
:::

## 2. 常用选项速查

| 选项 | 长选项 | 作用与使用场景 | 重要特点 |
| --- | --- | --- | --- |
| `-p` | `--parents` | 自动创建缺少的父级目录；目标目录已存在时不因“已存在”报错 | **最常用**，适合初始化项目、脚本 |
| `-m MODE` | `--mode=MODE` | 为命令行直接指定的新目录设置权限（八进制或符号模式） | **不会把该模式应用于 `-p` 创建的父目录** |
| `-v` | `--verbose` | 每成功创建一个目录就输出提示 | 配合 `-p` 查看创建层级 |
| `-Z` | — | 在支持 SELinux 的系统上设置新目录的默认安全上下文类型 | 需要 SELinux 支持 |
| `--context[=CTX]` | — | 设置 SELinux/SMACK 安全上下文（按系统支持情况） | 高级管理场景；非通用 |
| `--help` | — | 查看帮助 | GNU coreutils 提供 |
| `--version` | — | 查看版本 | GNU coreutils 提供 |
| `--` | — | 结束选项解析 | 名称以 `-` 开头时使用 |

**常见组合：** `-p`、`-pv`、`-m 700`、`-pm 700`、`-p -v -m 750`。选项顺序一般不影响这些组合的含义。

## 3. 使用场景速览

| 实际需求 | 主要用法 | 预期效果 |
| --- | --- | --- |
| 新建一个目录 | 默认模式 | 创建成功则目录出现；已存在则报错 |
| 创建多级项目结构 | `-p` | 缺失的父目录会自动补齐 |
| 在脚本里确保缓存目录存在 | `-p` | 已存在的目录不会引发“File exists”错误 |
| 批量创建兄弟目录 | Bash 花括号展开 + `-p` | 一条命令创建多个项目子目录 |
| 生成月份/编号目录 | Bash 序列展开 | 按规则生成多层目录 |
| 创建私有配置目录 | `-m 700` | 新目录只允许所有者访问 |
| 观察哪些目录真正被创建 | `-pv` | 逐级输出新建目录名 |
| 排查创建失败 | 权限、路径与目标类型 | 定位父目录权限或路径冲突 |

## 4. 实战示例（全部可折叠）

::: details 示例 1：创建单个目录和多个目录

```bash
# 在有写权限的当前目录运行
mkdir notes
mkdir images logs backups

# 检查创建结果
ls -ld notes images logs backups
```

**效果说明：** 创建 `notes/`、`images/`、`logs/`、`backups/`；这四个目标互不嵌套。

**易错点：** 再执行一次相同的命令，不加 `-p` 时会提示 `File exists`。

:::

::: details 示例 2：递归创建多级目录（-p）

```bash
mkdir -p project/src/utils

# 查看创建结果
find project -type d
```

**预期效果：** 如果 `project/`、`src/`、`utils/` 都不存在，命令会自动创建三层。

```text
project
project/src
project/src/utils
```

**特点：** 中间父目录已经存在时，`mkdir -p` 会直接使用它，而不会重建它。

:::

::: details 示例 3：在 Shell 脚本中确保目录存在

```bash
#!/usr/bin/env bash
set -e

cache_dir="$HOME/.cache/myapp"
mkdir -p -- "$cache_dir"

printf '缓存目录已就绪：%s\n' "$cache_dir"
```

**效果说明：** 适合在脚本启动时确保目录存在；重复运行通常不会因为目录已经存在而失败。

**注意：** 如果该路径已被一个**普通文件**占据、父目录无权限或文件系统只读，`-p` 仍然会失败。`-p` 不是“忽略一切错误”。

:::

::: details 示例 4：批量创建项目子目录（Bash 花括号展开）

```bash
mkdir -p demo/{src,include,tests,docs,build}

# 等价于依次指定这些目录
mkdir -p demo/src demo/include demo/tests demo/docs demo/build
```

**效果说明：** 自动建立常见 C/C++ 项目骨架，适合源码、头文件、测试、文档与构建产物分开存放。

**关键机制：** `{...}` 是 **Bash/Zsh 的 Shell 展开功能**，不是 `mkdir` 的选项；在不支持此语法的 `/bin/sh` 环境中不能直接照搬。

:::

::: details 示例 5：按年份与月份批量生成目录

```bash
# Bash 下创建 2026、2027 年的 01～12 月目录
mkdir -p archive/{2026..2027}/{01..12}

# 检查其中一个结果
ls -d archive/2026/*/
```

**预期效果：** 创建 `archive/2026/01/` 一直到 `archive/2027/12/`，共 24 个最末级月份目录。

**注意：** 花括号展开可能瞬间生成非常多参数。年/月范围很大时，先确认范围和 Shell 的参数长度限制。

:::

::: details 示例 6：创建只有自己可以访问的私有目录（-m）

```bash
# 仅属主拥有 rwx 权限
mkdir -m 700 private_data

# 查看实际权限
ls -ld private_data
```

**典型输出：**

```text
drwx------ ... private_data
```

**效果说明：** 属主可读、写、进入目录；同组用户和其他用户没有相应权限（仍需考虑 root、ACL 等其他机制）。

**特点：** 对直接指定的新建目录，GNU `mkdir -m` 可设置明确的权限模式；如果目录**已经存在**，该选项不会把旧目录的权限改成 700。

:::

::: details 示例 7：递归创建时指定权限（最容易误解的组合）

```bash
# 在临时工作区演示
workdir=$(mktemp -d)
cd "$workdir" || exit 1

mkdir -p -m 700 a/b/c
ls -ld a a/b a/b/c
```

**效果说明：** `a/b/c` 是命令行直接指定的目标目录，`-m 700` 用于它；自动补齐的 `a` 和 `a/b` **不保证也是 700**，其权限由 `mkdir -p` 的父目录创建规则、`umask` 等共同决定。

**如果每一层都要求严格权限：** 在受控的**新建**目录树中逐级创建并显式设置权限；对已存在的目录是否应修改权限，要先核实影响范围。

**易错点：** `-p -m 700` **不等于**“整棵目录树的每一层都自动变成 700”。

:::

::: details 示例 8：显示创建过程（-v）

```bash
mkdir -pv example/a/b/c
```

**典型输出（措辞可能因语言环境不同而变化）：**

```text
mkdir: created directory 'example'
mkdir: created directory 'example/a'
mkdir: created directory 'example/a/b'
mkdir: created directory 'example/a/b/c'
```

**效果说明：** 只有**实际新建**的目录才会输出创建提示。适合调试工程初始化脚本。

:::

::: details 示例 9：目录名带空格或以减号开头

```bash
mkdir "my project"
mkdir my\ notes

# 以下路径名以 - 开头，需要避免被当成选项
mkdir -- -temp
mkdir ./-cache
```

**效果说明：** 引号、反斜杠处理空格；`--` 或 `./` 处理以 `-` 开头的名称。

:::

::: details 示例 10：检查为什么无法创建目录

```bash
# 检查目标的父目录是否存在以及权限如何
ls -ld /path/to/parent

# 查看当前用户身份和所属组
id

# 查看当前默认权限掩码
umask

# 查看路径沿途目录的权限（如果安装了 namei）
namei -l /path/to/parent/newdir
```

**排查思路：** 先看路径有没有写错；再看沿途父目录是否可穿越（`x`），直接父目录是否允许创建条目（通常需 `w+x`）；最后确认磁盘/配额、只读挂载、安全策略等。

:::

## 5. 核心机制：目录权限与 `umask`

### 5.1 新建目录默认权限怎么来？

通常以目录基础权限 `0777` 为起点，应用 `umask` 掩码：

```text
最终权限 ≈ 0777 & ~umask
```

> 这里的 `&`、`~` 是**按位运算**，不是对所有情况都能简单使用普通十进制减法。还需考虑文件系统、ACL 等可能影响权限的因素。

| `umask` | 常见新目录权限 | 符号权限 | 效果 |
| --- | --- | --- | --- |
| `0022` | `0755` | `rwxr-xr-x` | 属主可写，其他用户可读/进入 |
| `0002` | `0775` | `rwxrwxr-x` | 同组用户通常也可写 |
| `0077` | `0700` | `rwx------` | 仅属主可访问 |
| `0027` | `0750` | `rwxr-x---` | 其他用户无访问权限 |

::: details 示例：验证默认权限与临时修改 umask

```bash
# 在子 Shell 中运行，不改变当前终端原来的 umask
(
  umask 077
  mkdir secure_dir
  ls -ld secure_dir
)
```

**预期效果：** 在没有额外 ACL 影响的常规文件系统上，目录通常显示为 `drwx------`。

**注意：** 括号创建子 Shell，因此 `umask 077` 不会永久影响外层 Shell。

:::

### 5.2 `-m`、`umask`、`-p` 有什么区别？

| 机制 | 影响对象 | 是否修改已经存在的目录 |
| --- | --- | --- |
| 默认创建规则 + `umask` | 普通新建目录的默认权限 | 否 |
| `-m MODE` | 命令行直接指定且新创建的目标目录 | 否 |
| `-p` | 允许自动创建缺失的父目录，并放宽“目录已存在”错误 | 否 |
| `chmod` | 对指定的现有对象改变权限 | **是**（需有足够权限） |

**重要补充：** `mkdir -p` 为了能继续创建下一层目录，会对新建父目录采用适当的父目录创建规则，因此不要把“中间目录权限 = 最终目录权限”当作不变规律。

### 5.3 创建子目录为什么需要父目录的 `w` 和 `x`？

- **`w`（写）**：允许修改父目录中的目录项（新增/删除/重命名条目时通常必需）。
- **`x`（执行/搜索）**：允许穿越父目录，以访问其中已知名称的条目。
- **`r`（读）**：主要用于读取目录项名称列表；仅有 `r` 并不等于能在目录里新建文件。

创建多级目录时，路径中各级目录的穿越权限也可能影响结果；root、ACL、SELinux 等还可能改变实际授权。

## 6. 报错与易错点

| 报错或现象 | 常见原因 | 正确处理思路 |
| --- | --- | --- |
| `File exists` | 目标已存在，且未使用 `-p` | 若要求幂等创建，使用 `-p`；若要求必须全新创建，保留默认行为 |
| `Not a directory` | 路径某一层其实是普通文件 | 检查路径各层类型；`-p` 不能把文件变成目录 |
| `Permission denied` | 无父目录写入/穿越权限，或安全策略限制 | 排查父目录权限、ACL、SELinux 等 |
| `No such file or directory` | 没有加 `-p` 且父目录不存在，或路径引用失效 | 检查中间路径，必要时使用 `-p` |
| `Read-only file system` | 目标所在文件系统只读 | 检查挂载状态；不是简单加 `sudo` 就能解决 |
| `No space left on device` | 磁盘空间或 inode 耗尽 | 检查 `df -h` 和 `df -i` |
| 加了 `-m 700`，父目录却不是 700 | `-m` 不覆盖 `-p` 自动创建的父目录 | 分别检查各层权限 |
| 在脚本中 `{a,b}` 创建出奇怪目录名 | Shell 不支持花括号展开，或进行了引用 | 换 Bash 运行，或改成显式多个参数 |
| 觉得 `-p` 会“重置”目录权限 | `-p` 对现有目录不会自动 `chmod` | 修改权限需明确使用 `chmod`，谨慎核对范围 |

## 7. 与相近工具的区别

| 工具 | 主要职责 | 说明 |
| --- | --- | --- |
| `mkdir` | 创建目录 | 可创建多层目录、设置初始权限 |
| `rmdir` | 删除**空目录** | 默认不删除非空目录 |
| `rm -r` | 递归删除目录及内容 | 有误删风险，不能当作 `rmdir` 的等价安全替代 |
| `touch` | 创建普通文件或更新时间戳 | **不会**创建目录 |
| `chmod` | 修改文件或目录权限 | 用于调整**已经存在**的对象 |
| `install -d` | 创建目录并可设置权限、属主/属组等 | 部署脚本中有时比 `mkdir` 更方便 |

## 8. 记忆重点

- **`mkdir -p`**：父目录缺失时补齐；目标已经是目录时不因存在而报错。
- **`mkdir -m MODE`**：设置新建目标目录权限，不自动覆盖各级父目录。
- **`mkdir -v`**：查看哪些目录成功创建。
- **`umask`**：参与默认新目录权限计算。
- **Shell 花括号**：属于 Shell 的参数展开，**不是** `mkdir` 自己解析的语法。
