# `mkdir` — 创建目录

`mkdir`（Make Directories）用于在 Linux 文件系统中创建一个或多个新目录，支持递归构建多层目录树及在创建瞬间原子化设定权限。

## 常用选项与说明

| 短选项 | 长选项 | 作用说明 |
| :--- | :--- | :--- |
| `-p` | `--parents` | **递归创建与幂等保护**：若父级目录不存在则自动顺次创建；若目标目录已存在则静默成功、不报错 |
| `-m` | `--mode=MODE` | **指定权限模式**：在创建目录的同时直接设置权限（支持八进制如 `700` 或符号模式如 `u=rwx,go=rx`），不受 `umask` 削减 |
| `-v` | `--verbose` | **详细输出模式**：每成功创建一个目录，就在终端打印一条创建记录信息 |
| `-Z` | `--context=CTX` | **设置安全上下文**：为新建目录指定 SELinux 安全上下文（RHEL/CentOS 常用；Ubuntu 默认使用 AppArmor，较少用到） |
| — | `--help` | 显示完整命令行帮助信息并退出 |
| — | `--version` | 显示版本信息与许可证声明并退出 |

---

## 典型使用场景

1. **初始化项目工程目录骨架**：结合 `-p` 与 Bash 花括号展开（Brace Expansion），一条命令一次性生成包含前后端、源码、测试、文档的标准化项目树。
2. **自动化部署与 CI/CD 脚本**：在 Shell 脚本中创建缓存、日志或构建目录时，强制使用 `mkdir -p`，确保重复运行脚本时不会因目录已存在而触发非零退出码中断流程。
3. **创建高安全隔离目录**：存放 SSH 密钥、TLS 私钥或环境变量配置时，使用 `mkdir -m 700` 直接以最严格权限创建，避免“先默认 `755` 创建再 `chmod 700`”之间存在的短暂权限暴露窗口（竞争条件）。

## 命令示例与效果说明

### 1. 递归创建多级嵌套目录并打印过程
```bash
mkdir -pv project/src/network/handlers
```
* **效果说明**：即使 `project`、`src`、`network` 均不存在，系统也会由外向内依次创建全部 4 级目录，并逐行输出 `mkdir: created directory 'project'` 等提示。

### 2. 结合花括号展开批量创建工程模块骨架
```bash
mkdir -p my_service/{cmd,internal/{handler,service,repo},configs,scripts}
```
* **效果说明**：由 Shell 在执行前先展开为多个完整路径参数，一次性构建出标准的 Go/C++ 后端工程目录树，无需逐个敲击命令。

### 3. 按年份与月份批量生成归档目录序列
```bash
mkdir -p /data/backups/{2025..2026}/{01..12}
```
* **效果说明**：自动生成 `2025` 和 `2026` 两个年份目录，并在每个年份下生成 `01` 到 `12` 共 24 个月份子目录。

### 4. 创建仅所有者可访问的私有目录（绕过 umask）
```bash
mkdir -m 700 ~/.ssh_keys
```
* **效果说明**：直接赋予目录 `rwx------`（`700`）权限，其他用户及同组用户均无权进入或查看该目录。

### 5. 创建名称包含空格或特殊符号的目录
```bash
mkdir -p "2026 Project Logs" 'backup_v1(final)'
```
* **效果说明**：使用双引号或单引号包裹含空格的目录名，防止 Shell 将空格解析为多个独立目录参数。

## 命令与选项的核心特点

* **权限计算底层机制（`0777 - umask`）**：
  * Linux 内核在调用 `mkdir()` 系统调用时，默认请求的基准权限为 `0777`（`rwxrwxrwx`）。
  * 最终实际生效的权限由当前 Shell 的权限掩码 `umask`（普通用户通常为 `0022`，root 通常为 `0022`）按位取反相与得出：`0777 & ~0022 = 0755`（`rwxr-xr-x`）。
  * 使用 `-m` 选项时，`mkdir` 会在创建后直接覆盖设置指定权限，不受默认 `umask` 限制。
* **操作幂等性（Idempotency）**：不带 `-p` 时，目标已存在会返回退出码 `1` 并报错 `File exists`；加上 `-p` 后，无论目录是否存在均返回退出码 `0`。

## 注意事项与易错点

1. **`-p` 与 `-m` 联用时的权限陷阱（极高频易错点）**：
   * **错误认知**：执行 `mkdir -pm 700 a/b/c` 时，很多人以为 `a`、`b`、`c` 三级目录都会被设为 `700`。
   * **实际情况**：`-m` **仅对最末端的目标目录（即 `c`）生效**！中间自动创建的父目录 `a` 和 `b` 依然遵循系统的默认 `umask`（通常为 `755`）。若需整棵子树均为 `700`，必须分步创建或在事后执行 `chmod -R 700 a`。
2. **花括号展开（`{a,b}`）不能加引号**：
   * 写成 `mkdir -p "app/{src,bin}"` 会导致花括号失效，直接创建一个字面量名为 `{src,bin}` 的文件夹。花括号展开必须裸露在引号外部（如 `app/{src,bin}`）。
3. **父目录权限不足报错**：
   * 在某个目录下新建子目录，本质是在修改父目录的数据块（写入新的目录项），因此你必须对**父目录同时拥有写（`w`）和执行（`x`）权限**，缺一不可，否则报错 `Permission denied`。
4. **文件名以 `-` 开头的安全创建**：
   * 若必须创建以连字符开头的目录（如 `-test`），需使用 `mkdir -- -test` 或 `mkdir ./-test`，防止参数解析器将其误判为无效选项。
