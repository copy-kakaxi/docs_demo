# `grep` — 文本模式搜索与正则匹配引擎

`grep`（Global Regular Expression Print）是 Linux 文本处理“三剑客”之一，用于按行扫描文件或标准输入，筛选并输出符合指定字符串或正则表达式模式的行。

## 常用选项与说明

| 短选项 | 长选项 | 作用说明 |
| :--- | :--- | :--- |
| `-i` | `--ignore-case` | **忽略大小写**：匹配时不区分英文字母的大小写（如同时匹配 `Error`、`ERROR`、`error`） |
| `-v` | `--invert-match` | **反向匹配（取反）**：仅输出**不包含**匹配模式的行（常用于过滤注释行和空行） |
| `-E` | `--extended-regexp` | **启用扩展正则（ERE）**：支持 `+`、`?`、`|`、`()`、`{m,n}` 等元字符，无需反斜杠转义（等价于旧版 `egrep`） |
| `-P` | `--perl-regexp` | **启用 Perl 兼容正则（PCRE）**：支持 `\d`、`\s`、非贪婪匹配 `.*?` 及零宽断言（Lookaround） |
| `-F` | `--fixed-strings` | **固定纯字符串匹配**：关闭所有正则元字符解析，按字面量匹配，搜索速度最快（等价于 `fgrep`） |
| `-r` / `-R` | `--recursive` | **递归搜索目录**：`-r` 递归搜索目录下所有文件（不跟随目录软链接）；`-R` 会跟随所有符号链接 |
| `-n` | `--line-number` | **显示行号**：在每条匹配结果的开头打印其在原文件中的行号 |
| `-c` | `--count` | **仅统计匹配行数**：不打印具体文本内容，只输出每个文件中匹配到的总行数 |
| `-l` | `--files-with-matches` | **仅列出匹配的文件名**：只要文件中有任意一行匹配，就打印该文件路径并立即跳过该文件剩余部分 |
| `-L` | `--files-without-match` | **列出不包含匹配项的文件名**：找出完全没有出现目标关键词的文件 |
| `-o` | `--only-matching` | **仅输出匹配到的片段本身**：剥离整行其他字符，只把命中正则的子串单独成行打印（配合 `wc -l` 可统计单词出现总次数） |
| `-w` | `--word-regexp` | **全词精确匹配**：要求匹配模式必须构成独立单词（前后为非单词字符或行首尾，避免 `cat` 误匹配 `concatenate`） |
| `-A <N>` | `--after-context=NUM` | **显示后 N 行（After）**：打印匹配行及其**之后**的 `N` 行上下文（排查 Java/Python 异常堆栈必备） |
| `-B <N>` | `--before-context=NUM` | **显示前 N 行（Before）**：打印匹配行及其**之前**的 `N` 行上下文 |
| `-C <N>` | `--context=NUM` | **显示前后各 N 行（Context）**：同时打印匹配行上下各 `N` 行内容 |
| — | `--include=GLOB` | **仅搜索指定后缀文件**：配合 `-r` 使用，如 `--include="*.cpp"` |
| — | `--exclude-dir=DIR` | **排除指定目录**：配合 `-r` 使用，如 `--exclude-dir={.git,node_modules,build}` |
| — | `--color=auto` | **高亮匹配关键词**：在终端输出时对命中的子串标红高亮，重定向到文件或管道时自动取消颜色码 |

## 典型使用场景

1. **生产环境日志排障与堆栈追踪**：使用 `grep -rnE "ERROR|FATAL" -A 15 /var/log/app/` 递归检索所有错误日志，并向下展开 15 行完整打印出调用栈（Stack Trace）。
2. **提取干净的有效配置文件**：通过管道串联 `grep -vE '^\s*#|^\s*$'`，一键过滤掉配置文件中的 `#` 注释行和纯空白行，只看生效的核心参数。
3. **大型代码库精准符号检索**：在 C/C++ 或大型工程中，利用 `--include` 限制源码后缀、`--exclude-dir` 跳过编译产物与 `.git` 目录，实现毫秒级函数与变量定义定位。
4. **结合正则提取结构化字段**：利用 `-oP` 配合 Perl 零宽断言，从非结构化日志中精准抽取 IP 地址、HTTP 状态码或耗时数值。

## 命令示例与效果说明

### 1. 过滤配置文件中的注释行与空白行
```bash
grep -vE '^\s*(#|$)' /etc/nginx/nginx.conf
```
* **效果说明**：`^\s*#` 匹配以任意空白符加 `#` 开头的注释行，`^\s*$` 匹配空行或纯空格行；`-v` 将其全部剔除，仅打印实际生效的配置指令。

### 2. 检索报错并向下展开 10 行异常堆栈
```bash
grep -in -A 10 "OutOfMemoryError" catalina.out
```
* **效果说明**：忽略大小写（`-i`）定位 `OutOfMemoryError`，打印所在行号（`-n`），并紧接着输出后续 10 行（`-A 10`）详细堆栈，方便定位触发内存溢出的具体类与方法。

### 3. 在源码工程中递归查找函数调用（排除干扰目录）
```bash
grep -rnw --include="*.{c,cpp,h}" --exclude-dir={.git,build,third_party} "epoll_wait" ./src/
```
* **效果说明**：仅在 `./src/` 下的 C/C++ 源码与头文件中，全词精确匹配（`-w`）`epoll_wait`，自动跳过 `.git`、`build` 等庞大无关目录，避免检索卡死。

### 4. 利用 Perl 正则零宽断言精准提取日志中的 IP 地址
```bash
grep -oP '(?<=client: )\d{1,3}(\.\d{1,3}){3}' /var/log/nginx/error.log
```
* **效果说明**：`(?<=client: )` 为正向后行断言（只匹配前缀而不输出前缀），`-o` 确保每行只输出纯粹的 IPv4 地址，可直接通过管道交给 `sort | uniq -c | sort -nr` 统计 Top 攻击 IP。

### 5. 批量查找包含敏感配置的文件名列表
```bash
grep -rl "DB_PASSWORD" /etc/ /opt/apps/ 2>/dev/null
```
* **效果说明**：`-l` 使 `grep` 在每个文件中命中第一条记录后立即停止扫描该文件并打印其路径，`2>/dev/null` 屏蔽无权限访问目录的报错信息。

## 命令与选项的核心特点

* **三引擎正则架构**：
  * **BRE（基础正则，默认）**：`+`、`?`、`|`、`()` 均视为普通字符，必须写为 `\+`、`\?`、`\|`、`\(\)` 才具有正则含义。
  * **ERE（扩展正则，`-E`）**：上述元字符直接生效，语法现代统一，**日常使用强烈建议默认加上 `-E`**。
  * **PCRE（Perl 正则，`-P`）**：功能最强，支持前后向断言、非贪婪匹配及快捷字符类（`\d`、`\w`），但在极少数精简版嵌入式系统（如 BusyBox）中可能未编译该特性。
* **退出状态码（Exit Code）具有明确语义**：
  * `0`：至少找到 1 行匹配结果。
  * `1`：未找到任何匹配结果（注意：在 Shell 脚本若开启 `set -e` 时，`grep` 查无结果返回 `1` 会导致脚本直接异常退出，需写为 `grep ... || true`）。
  * `2`：发生系统级错误（如文件不存在、无读取权限或正则表达式语法错误）。
* **底层 Boyer-Moore 算法加速**：GNU `grep` 底层采用 Boyer-Moore 字符串搜索算法，无需逐字节扫描整个文本即可大跨度跳跃比对，处理 GB 级纯文本的速度远超 Python/Java 等常规脚本循环。

## 注意事项与易错点

1. **混淆 Shell 通配符（Glob）与正则表达式（Regex）**：
   * **易错原因**：在文件名匹配中 `*` 代表“任意字符”，但在正则中 `*` 代表**“前一个字符出现 0 次或多次”**。直接写 `grep "error*" file.log` 实际匹配的是 `erro` 后跟零个或多个 `r`（连 `erro` 都会被匹配）。
   * **正确写法**：匹配任意长度字符应使用 `.*`（如 `grep -E "error.*timeout" file.log`）。
2. **正则表达式未加单引号导致被 Shell 提前展开**：
   * 若写为 `grep $PATH file.txt` 或不加引号的 `grep * file.txt`，双引号内的 `$` 会被 Bash 解析为环境变量，`*` 会被展开为当前目录下的所有文件名，导致匹配完全失真。**正则表达式必须始终用单引号 `'...'` 包裹**。
3. **搜索包含 `-` 开头的关键词被误认为选项**：
   * 例如想在日志中搜索 `--debug` 参数，直接写 `grep "--debug" app.log` 会报错 `unrecognized option '--debug'`。
   * **解决方法**：使用 `-e` 显式指定模式（`grep -e "--debug" app.log`）或使用 `--` 终止选项解析（`grep -- "--debug" app.log`）。
4. **管道中滥用 `grep` 导致“猫的滥用”（Useless Use of Cat）**：
   * 避免写成 `cat app.log | grep "ERROR"`，多启动一个 `cat` 进程和管道缓冲区不仅浪费性能，还可能导致 `grep` 无法获取文件名。直接写 `grep "ERROR" app.log` 即可。
