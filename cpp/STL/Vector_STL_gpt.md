## 一、构造函数

| 构造方式 | 形式 / 示例 | 说明 |
| --- | --- | --- |
| 默认构造 | `vector<T> v;` | 创建空 `vector`。 |
| 指定大小构造 | `vector<T> v(n);` | 创建包含 `n` 个默认初始化元素的 `vector`。 |
| 指定大小与值 | `vector<T> v(n, value);` | 创建包含 `n` 个 `value` 副本的 `vector`。 |
| 范围构造 | `vector(InputIterator first, InputIterator last);` | 从迭代器区间构造。 |
| 拷贝构造 | `vector(const vector& other);` | 从另一个 `vector` 拷贝构造。 |
| 移动构造（C++11） | `vector(vector&& other) noexcept;` | 将 `other` 的元素移动到新 `vector`。 |
| 初始化列表构造（C++11） | `vector(initializer_list<T> init);` | 通过初始化列表创建。 |

初始化列表示例：

```cpp
vector<int> v = {1, 2, 3, 4, 5};
```

## 二、成员函数：容量与访问

> 原表将此组归为 **12 个函数 / 操作**；其中有些函数合并写在同一行。

| 函数 / 操作 | 作用 | 重点提示 |
| --- | --- | --- |
| `front()` / `back()` | 返回首元素 / 尾元素的引用。 | 获取元素内容；对空容器调用会导致**未定义行为**。 |
| `size()` | 返回当前容器中元素的个数。 | 表示已有元素数。 |
| `empty()` | 判断容器是否为空。 | 空则返回 `true`；原表提示通常比 `size() == 0` 更高效。 |
| `capacity()` | 返回当前已分配的存储空间大小。 | 即扩容前最多能容纳的元素个数；`capacity() >= size()`。 |
| `reserve(n)` | 预留至少容纳 `n` 个元素的存储空间。 | 预估数据量后提前预留容量，可避免插入过程中反复扩容；**不改变 `size()`**。 |
| `resize(n, val)` | 调整实际元素个数（`size`）。 | `n > size` 时扩充并用 `val` 填充；`n < size` 时截断尾部；可能改变 `capacity`。 |
| `shrink_to_fit()` | 请求移除未使用的容量（C++11）。 | 原表表述为缩减 `capacity` 至 `size`，用于节约内存。**注意：这是非强制请求，不保证一定缩减。** |
| `operator[]` / `at(pos)` | 访问指定索引的元素。 | `v[0]` 不检查越界；`v.at(0)` 检查边界，越界抛出 `std::out_of_range`。 |
| `data()` | 返回指向底层连续数组的指针。 | 返回 `T*`，用于对接 `memcpy`、`recv` 等需要原始指针的 C 风格接口。 |
| `assign(...)` | 替换已有容器的内容。 | 构造函数用于创建时初始化；`assign()` 用于修改已有对象。 |

### `size()` 与 `capacity()` 的区别

- `size()`：**当前实际有多少个元素**。
- `capacity()`：**当前已分配的空间最多能容纳多少个元素**。
- `reserve(n)`：主要用于**提前分配空间**，不直接添加元素。
- `resize(n, val)`：直接改变**元素数量**，必要时也可能扩大分配空间。

## 三、成员函数：修改与增删

> 原表归纳为 **7 个函数**。

| 函数 / 操作 | 作用 | 重点提示 |
| --- | --- | --- |
| `push_back(val)` | 在末尾添加一个元素。 | 可能执行拷贝或移动构造；空间不足时会自动扩容。 |
| `pop_back()` | 删除末尾的一个元素。 | 返回 `void`，**不返回被删元素的值**。 |
| `emplace_back(args...)` | 在末尾直接构造元素（C++11）。 | 通过传递构造参数，可避免先创建临时对象再插入；原表强调它比 `push_back` 更高效。 |
| `insert(pos, val)` | 在迭代器 `pos` 指定的位置**之前**插入内容。 | 可插入单个元素、`n` 个元素或一个区间；插入点后的元素可能整体后移，开销较大。 |
| `erase(pos)` | 删除指定位置或 `[first, last)` 区间的元素。 | 后续元素向前移动；返回指向被删区域之后元素的新迭代器。 |
| `clear()` | 清空所有元素。 | `size()` 变为 `0`，但 **`capacity()` 通常保持不变**。 |
| `swap(v2)` | 交换两个 `vector` 的内容。 | `v1.swap(v2)` 通常非常高效；原表将其描述为交换内部三个指针 `begin`、`end`、`capacity_end`，无需逐个拷贝元素。 |

## 四、常用泛型算法

> 原表分类：需使用 `<algorithm>` 或 `<numeric>`。下面按功能重新归组，便于查找。代码中 `s`、`v`、`v1`、`v2` 沿用原表变量名。

### 4.1 排序、反转、复制与填充

| 操作 | 示例代码 | 说明 |
| --- | --- | --- |
| 排序（升序 / 降序） | `std::sort(s.begin(), s.end());` | 原表提供了默认排序写法。 |
| 反转 | `std::reverse(s.begin(), s.end());` | 反转元素顺序；原表旁注为“变成 edabc”。 |
| 复制容器内容 | `std::copy(v1.begin(), v1.end(), v2.begin());` | 从源区间复制到目标区间。 |
| 填充 | `std::fill(v.begin(), v.end(), 1);` | 将区间内所有元素赋值为 `1`；原表将它与 C 语言 `memset` 对照。 |

**`std::copy` 的重要提醒**

原表还有以下示例：

```cpp
std::copy(vec.begin(), vec.end(), dest.begin());
```

`std::copy` **不会自动扩容目标容器**。它从 `dest.begin()` 开始写入，覆盖现有位置；如果目标区间空间不足，会越界写入并引发未定义行为（例如数据损坏、崩溃）。因此，使用这种写法时，目标容器应先通过 `resize()` 等方式准备足够的**实际元素空间**，而不仅仅是 `reserve()`。

### 4.2 查找、计数与最大最小值

| 操作 | 示例代码 | 说明 |
| --- | --- | --- |
| 查找元素 | `auto it = std::find(s.begin(), s.end(), 'a');` | 返回迭代器；原表还列出 `find_if()`。 |
| 统计元素数量 | `int count = std::count(s.begin(), s.end(), 'a');` | 原表还列出 `count_if()`。 |
| 最大值所在位置 | `std::max_element(s.begin(), s.end());` | 返回最大值的迭代器；字符例子中按字符编码比较（原表写为 ASCII 码）。 |
| 最小值所在位置 | `std::min_element(s.begin(), s.end());` | 返回最小值的迭代器。 |

### 4.3 去重与移除：注意“逻辑末尾”

**去重：`std::unique` + `erase`**

```cpp
s.erase(std::unique(s.begin(), s.end()), s.end());
```

原表强调：

- `std::unique` 只能合并**相邻的重复元素**；如果要去除所有相同值，一般应先 `sort()`，再 `unique()`。
- `unique()` 会把保留的元素向前移动，并返回去重后序列的**新逻辑末尾迭代器**。
- `unique()` **不会自动缩小 `vector` 的 `size()` 或 `capacity()`**，需搭配 `erase()` 删除多余的尾部元素。

**移除：`std::remove` + `erase`**

```cpp
auto it = std::remove(s.begin(), s.end(), 'l');
s.erase(it, s.end());
```

`remove()` 把不需要移除的有效元素向前重组，返回**新逻辑末尾迭代器**；真正缩小容器还需要调用 `erase()`。

> 两者的共同点：`unique()` / `remove()` 做的是元素重排，`erase()` 才改变容器的实际元素数量。

### 4.4 累加、变换与逐个处理

**`std::accumulate`：累积计算**

```cpp
#include <numeric>

int sum = std::accumulate(v.begin(), v.end(), 0);
```

- 默认行为是从前向后累加：`0 + a + b + c + ...`。
- 第三个参数 `0` 是**初始值**；其类型也决定累加结果的计算类型。为避免整型溢出风险，可按需要改用 `0LL`。
- 原表还提到多参数版本：可使用自定义二元操作，例如连乘 `1 × a × b × c × ...`；减法等非交换运算需要特别留意运算顺序。

**`std::transform`：转换大小写**

```cpp
std::transform(s.begin(), s.end(), s.begin(), ::toupper);
```

原表备注：第三个参数位置写的是输出起始迭代器；其中 `::toupper` 或 `::tolower` 是执行字符转换的函数。

**`std::for_each`：遍历处理**

```cpp
std::for_each(s.begin(), s.end(), [](char& c) {
    c += 1;
});
```

**`std::replace`：替换元素**

```cpp
std::replace(s.begin(), s.end(), 'l', 'L');
```

**`std::swap`：交换两个对象**

```cpp
std::swap(s1, s2);
```

原表还给出了 `s1.swap(s2)`，并强调对字符串等容器，交换内部资源通常不需要逐个复制成千上万个字符。

## 五、底层交互与 C 风格操作

原表核心观点：`vector` 的元素**连续存储**，因此能够像 C 风格数组一样与底层接口交互。

### 5.1 传给 C 语言接口：`data()`

```cpp
void c_func(int* arr, int len);

// 已有 vector<int> v
c_func(v.data(), v.size());
```

`v.data()` 是连接 C++ `vector` 和原始指针接口的桥梁。原表还提到：旧版本 C++ 常用 `&v[0]`；**注意空容器不能对 `v[0]` 取址**。

### 5.2 C 风格内存初始化：`memset`

原表提供了以下写法：

```cpp
memset(v.data(), 0, v.size() * sizeof(int));
```

**原表的强烈警告：** 这种字节级操作只能在适合进行原始字节写入的元素类型上使用，例如用于整型元素的清零。**不能**用它直接重置 `vector<string>` 等包含非平凡类对象的容器，否则可能破坏对象内部结构。一般赋值初始化更推荐 `std::fill`：

```cpp
std::fill(v.begin(), v.end(), 0);
```

## 六、与 `std::string` 的对照

| `std::string` | `std::vector` | 原表对照说明 |
| --- | --- | --- |
| `c_str()` | `data()` | 原表用两者类比底层数据访问；使用 `vector` 时得到的是元素类型对应的指针。 |
| `length()` / `size()` | `size()` | `vector` 没有 `length()`，只能用 `size()`。 |
| `append()` / `+=` | `push_back()` / `insert()` | 都可向容器增加内容，但具体参数与语义不同。 |

## 七、扩容与迭代器失效

原表特别强调：和 `string` 的内存重分配可能让此前取得的 `const char*` 悬空一样，**当 `vector` 发生重新分配内存的扩容时**，原先指向元素的迭代器和底层指针（例如 `data()` 的返回值）都会失效。

例如，`push_back()` **可能**触发扩容。一旦触发重新分配，之前保留的指针、引用和迭代器都不能继续使用。这是常见笔试与面试考点。

> **重要区别：** `push_back()` 不等于每次都会扩容；只有发生重新分配时，才出现上述全体失效的情况。原表重点讨论的是“扩容之后”的失效风险。

## 附录：原表中的 `std::deque` 失效规则

> 以下三条出现在 **Vector** 工作表的最后几行，但讨论对象实际上是 `deque`。为完整保留原表内容，单独收录在附录，而不混入 `vector` 的失效规则。

### 1. 在中间插入 / 删除：`insert`、`erase`

原表称为“灾难性失效”：在中间插入或删除元素时，`deque` 中的**所有迭代器、指针和引用都可能失效**；原表解释为内部调整元素位置以腾出空间或填补空缺。

### 2. 在首尾插入：`push_front`、`push_back`

原表强调一个反直觉点：

- **迭代器失效**：原表写为“所有迭代器可能失效”，并用内部中控器（`map`）可能重新分配解释原因。
- **指针 / 引用仍有效**：指向已有元素的指针和引用仍有效；原表解释为存放元素的内存块本身没有被移动或销毁。

### 3. 在首尾删除：`pop_front`、`pop_back`

原表的概括：**仅被删除元素**的迭代器和引用失效，其他元素不受影响。
